# Chiptune Synthesizer User Manual

8 channels, "SNES flavor" — mathematically synthesized waveforms (not
recorded samples, unlike the real SPC700), each with a full ADSR
envelope, stereo panning, portamento, dynamic duty cycle, and an
optional built-in sequencer. Any channel can be any waveform; none has
a fixed role.

## 1. Register layout

Each channel is a **32-byte** block, starting at `CHIPTUNE_BASE`
(`0xC300`). Channel N's base address = `CHIPTUNE_BASE + N * CHIPTUNE_CH_STRIDE`.

| Offset (named) | Field | Range |
|---|---|---|
| `CHIPTUNE_FREQ_OFFSET` (0) | Frequency, Hz — or LFSR clock rate if waveform=noise | 0–65535 |
| `CHIPTUNE_CTRL_OFFSET` (2) | Gate + waveform + duty (see §2) | — |
| `CHIPTUNE_VOLUME_OFFSET` (4) | Channel volume | 0–255 |
| `CHIPTUNE_ATTACK_OFFSET` (6) | Attack time, ms | 0–65535 |
| `CHIPTUNE_DECAY_OFFSET` (8) | Decay time, ms | 0–65535 |
| `CHIPTUNE_SUSTAIN_OFFSET` (10) | Sustain level | 0–255 |
| `CHIPTUNE_RELEASE_OFFSET` (12) | Release time, ms | 0–65535 |
| `CHIPTUNE_PAN_OFFSET` (14) | Stereo pan: 0=left, 128=center, 255=right | 0–255 |
| `CHIPTUNE_PORTAMENTO_OFFSET` (16) | Pitch glide time, ms (0 = instant, the old behavior) | 0–65535 |
| `CHIPTUNE_DUTY_SWEEP_OFFSET` (18) | ms for one full PWM sweep cycle (0 = static duty, from CTRL) | 0–65535 |
| `CHIPTUNE_SEQ_PTR_OFFSET` (20) | Address (in CPU RAM) of this channel's note table | 0–65535 |
| `CHIPTUNE_SEQ_CTRL_OFFSET` (22) | Sequencer control: bit0=playing, bit1=loop | — |

There's no named constant per channel (same convention as PPU sprites)
— compute the address yourself:

```asm
MOV R0, CHANNEL_NUMBER
MOV R1, CHIPTUNE_CH_STRIDE
MUL R0, R1
ADD R0, CHIPTUNE_BASE          ; R0 = base address of that channel
```

## 2. `CTRL` — Gate, waveform, duty

| Bits | Field |
|---|---|
| 0 | Gate (1 = note held, 0 = released) — **ignored while the sequencer is playing this channel, see §9** |
| 1–2 | Waveform |
| 3–4 | Duty (square wave only, and only when `DUTY_SWEEP` is 0 — see §6) |

```
CHIPTUNE_CTRL_GATE           = 0x0001
CHIPTUNE_CTRL_WAVEFORM_MASK  = 0x0006
CHIPTUNE_CTRL_WAVEFORM_SHIFT = 1
CHIPTUNE_CTRL_DUTY_MASK      = 0x0018
CHIPTUNE_CTRL_DUTY_SHIFT     = 3
```

Waveforms: `CHIPTUNE_WAVEFORM_SQUARE` (0), `_TRIANGLE` (1), `_SAWTOOTH`
(2), `_NOISE` (3). Duty (square only): `CHIPTUNE_DUTY_12_5` (0), `_25`
(1), `_50` (2), `_75` (3) — a narrower duty sounds thinner/reedier, a
wider one fuller.

```asm
MOV R1, CHIPTUNE_CTRL_GATE
MOV R2, CHIPTUNE_WAVEFORM_SQUARE
SHL R2, CHIPTUNE_CTRL_WAVEFORM_SHIFT
OR R1, R2
MOV R2, CHIPTUNE_DUTY_50
SHL R2, CHIPTUNE_CTRL_DUTY_SHIFT
OR R1, R2
STORE R1, [R0]                  ; R0 = this channel's base address
```

## 3. The ADSR envelope

Standard 4-stage envelope, same shape used by most real synths:

1. **Attack** — volume ramps `0 → 1.0` over `ATTACK` ms, starting the
   instant `Gate` goes from 0 to 1.
2. **Decay** — ramps `1.0 → SUSTAIN` (as a fraction of 255) over
   `DECAY` ms.
3. **Sustain** — holds at that level for as long as `Gate` stays 1.
4. **Release** — ramps from wherever the envelope currently is down to
   `0`, over `RELEASE` ms, starting the instant `Gate` goes from 1 to 0.

Any stage with a time of `0` ms is instantaneous. **Leaving `DECAY` at
0 (the default) makes Attack jump straight to Sustain** — fine for a
sustained tone, but if you're retriggering the *same* pitch repeatedly
(e.g. a drum, or repeated notes in a melody), a real `DECAY` value
makes each hit clearly distinct instead of blurring together.

## 4. Stereo panning

`PAN` (0–255) sets a constant-power stereo position: `0` = full left,
`128` = centered (the default after Reset — you don't need to set this
unless you want off-center placement), `255` = full right.

```asm
MOV R0, CHIPTUNE_BASE
ADD R0, CHIPTUNE_PAN_OFFSET
MOV R1, 0
STORE R1, [R0]      ; this channel plays entirely in the left ear
```

## 5. Portamento — pitch glide

`PORTAMENTO` (ms) makes `FREQ` changes glide smoothly instead of
jumping instantly (the default, `0`, is the original instant-jump
behavior). The larger the value, the slower the glide. Keep `Gate` held
(don't re-trigger) while sliding between pitches, or you'll hear a
fresh pluck at each new target instead of a pure glide:

```asm
STORE R1, [R0]     ; R1 = new target FREQ, R0 = this channel's FREQ address - the pitch eases toward it over PORTAMENTO ms
```

## 6. Dynamic duty cycle (PWM sweep)

`DUTY_SWEEP` (ms for one full sweep cycle) makes a square-wave
channel's duty cycle continuously oscillate between roughly 12.5% and
87.5% instead of staying fixed — the classic "wobbling" NES PWM lead
sound. While active, the static `Duty` bits in `CTRL` are ignored.
`0` (the default) means static duty, using whatever `CTRL` specifies.

## 7. The noise channel

Waveform `NOISE` doesn't have a "pitch" in the usual sense — it's
generated by a 15-bit LFSR (same technique real NES/Game Boy/SID chips
used), and `FREQ` controls how fast the LFSR advances instead of a
tone frequency. Higher values give a brighter/hissier noise (good for
hi-hats), lower values a duller/rumblier one (good for snares, or a
"low thud" alongside a pitched kick).

## 8. Retriggering a note manually — a critical gotcha

The envelope only restarts (`Attack` phase) on a **rising edge** of
`Gate` — going from 0 to 1. If you write `Gate=1` again while it's
*already* 1 (e.g. hitting the same drum channel repeatedly without
ever clearing `Gate` in between), **nothing retriggers**.

**Always clear `Gate` to 0, wait a few milliseconds, then set it back
to 1** for each new hit on the same channel, when doing this by hand
in assembly — the short wait matters: the engine only samples your
registers once per engine tick (~60/sec), so writing 0 then 1
back-to-back in the same tick can be invisible to it, especially at
high MIPS.

```asm
; correct: turn off, wait a beat, turn on - guarantees the edge
STORE R2, [R0]        ; CTRL with Gate=0
MOV R1, 5
CALL WAIT_MS
STORE R1, [R0]          ; CTRL with Gate=1 -> actually triggers
```

**The built-in sequencer (§9) doesn't have this limitation** — it can
retrigger the same pitch back-to-back with no audible gap, because it
drives the envelope directly rather than relying on you seeing a 0
in between.

## 9. The built-in song sequencer

Point `SEQ_PTR` at a table of `(FREQUENCY, DURATION_MS)` word pairs in
CPU RAM (built with `.DW`), terminated by a `0` duration, then set
`SEQ_CTRL`'s playing bit — the engine reads the table and plays it
automatically, handling all timing and retriggering for you.

```asm
SONG:
    .DW 659, 250, 622, 250, 659, 250, 622, 250, 659, 500, 0, 0
```

A frequency of `0` in an entry is a **rest** (silence for that
duration, no note played). The `0, 0` pair at the end stops playback
(or, if the loop bit is set, jumps back to the start).

```asm
MOV R0, CHIPTUNE_BASE
ADD R0, CHIPTUNE_SEQ_PTR_OFFSET
MOV R1, SONG
STORE R1, [R0]

MOV R0, CHIPTUNE_BASE
ADD R0, CHIPTUNE_SEQ_CTRL_OFFSET
MOV R1, CHIPTUNE_SEQ_CTRL_PLAYING   ; add CHIPTUNE_SEQ_CTRL_LOOP too, for a looping song
STORE R1, [R0]
```

**You still need to configure everything else yourself** —
`VOLUME`/`ATTACK`/`DECAY`/`SUSTAIN`/`RELEASE`/`PAN`, and crucially the
**waveform bits of `CTRL`** (the sequencer never touches `CTRL`, only
`FREQ` and the internal Gate state — leaving `CTRL` untouched means
you get waveform `0`/square by default, which may not be what you
want).

**While a channel's sequencer is playing, that channel's `Gate` bit in
`CTRL` is ignored** — the sequencer owns note on/off for that channel
until playback stops (either it reaches the end, or you clear the
playing bit yourself).

## 10. Playing several channels at once

There's no special mechanism needed — each channel is fully
independent. Configure and gate as many as you like; the mixer sums
them automatically (with soft-clipping, see §11).

## 11. Mixing and volume

All 8 channels are summed and soft-clipped (a gentle compression near
the limit, not a hard cutoff) rather than divided by a fixed amount —
so a single channel plays at its real, full volume, and several loud
channels playing together compress smoothly instead of harshly
distorting.

## 12. Playback continues through Pause, breakpoints, and HLT

Chiptune audio (manual notes and the sequencer alike) behaves like the
Timer/RTC — it keeps running in real time regardless of whether the
CPU is executing. This is deliberate: a program that triggers a
background song via the sequencer and then does other work (or simply
halts) expects the music to keep playing, not cut out the instant the
CPU stops. **Only a full `Reset` silences it.**

(The PC Speaker is the exception — it still stops immediately on
Pause/breakpoint/HLT, which fits its typical "quick beep" use better
than background music.)

## 13. Recipes — approximating instrument types

None of these are real recordings — they're the closest a 4-waveform
generator gets, using waveform choice + ADSR shaping:

| Instrument | Waveform | ADSR shape |
|---|---|---|
| **Bass** | Triangle | Fast attack, short decay, **high** sustain (bass notes hold) |
| **Guitar/pluck** | Square, narrow-to-medium duty | Fast attack, noticeable decay to a **lower** sustain (notes fade after the pluck); detuning 2 of several simultaneous notes by ±1-2 Hz adds a chorus-like shimmer |
| **Pad/strings** | Triangle or sawtooth | Slow-ish attack, long sustain; a subtle `PORTAMENTO` (§5) adds a natural glide between notes |
| **Lead synth** | Square with `DUTY_SWEEP` active (§6) | Medium attack/sustain — the PWM wobble gives it movement |
| **Kick drum** | Triangle, low frequency (~60 Hz) | Instant attack, very short decay, sustain 0 |
| **Snare** | Noise, mid rate (~2000–4000) | Instant attack, short decay, sustain 0 |
| **Hi-hat** | Noise, high rate (~8000+) | Instant attack, very short decay, sustain 0 |
| **Footsteps** | Noise, low-mid rate, varying slightly per step | Instant attack, short decay, sustain 0 |

## 14. Current limitations

- No filter (no low-pass/high-pass tone shaping).
- No song data format beyond flat `(FREQ, DURATION)` pairs — no
  per-note volume/waveform changes, no chords within a single
  channel's sequence (use multiple channels, each with its own
  sequencer, for that).
- Sample-based channels (real recorded instrument timbres, like the
  actual SPC700) remain a bigger, separate undertaking — see the
  original design discussion for this device.
